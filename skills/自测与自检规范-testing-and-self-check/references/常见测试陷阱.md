# 常见测试陷阱

测试反面模式、识别方法与规避策略。

---

## 陷阱 1：只测 Happy Path

| 项目 | 说明 |
|------|------|
| **症状** | 测试用例全是正常输入，没有边界和异常 |
| **危害** | 生产环境一旦出现异常输入就崩溃 |
| **识别** | 检查测试文件，是否只有 `test_success`、`test_normal` 这类用例 |
| **规避** | 强制要求每个函数至少 3 个测试：正常 + 边界 + 异常 |

**错误示例：**

```javascript
// ❌ 只有 Happy Path
it('should work', () => {
  expect(process({ name: 'Alice', age: 30 })).toBe(true);
});
```

**正确示例：**

```javascript
// ✅ 覆盖三种路径
it('should process valid user', () => { ... });
it('should reject user with empty name', () => { ... });
it('should reject user with negative age', () => { ... });
it('should handle null input gracefully', () => { ... });
```

## 陷阱 2：过度 Mock

| 项目 | 说明 |
|------|------|
| **症状** | Mock 了被测函数本身，或 Mock 了所有依赖导致测试空洞 |
| **危害** | 测试通过但功能实际已坏，失去测试意义 |
| **识别** | 测试代码中大量 `jest.mock` / `mock.patch`，且被测逻辑未真正执行 |
| **规避** | 只 Mock 外部依赖（API、数据库、文件系统），不 Mock 被测对象 |

**错误示例：**

```python
# ❌ Mock 了被测函数本身
@patch('module.calculate')
def test_calculate(mock_calc):
    mock_calc.return_value = 42
    result = calculate(1, 2)
    assert result == 42  # 测了个寂寞
```

**正确示例：**

```python
# ✅ Mock 外部依赖，测真实逻辑
@patch('module.external_api_call')
def test_calculate(mock_api):
    mock_api.return_value = 10
    result = calculate(1, 2)  # calculate 的真实逻辑被执行
    assert result == 13
```

## 陷阱 3：脆弱测试（Flaky Test）

| 项目 | 说明 |
|------|------|
| **症状** | 有时通过有时失败，与代码逻辑无关 |
| **危害** | 开发者不信任测试，忽略失败警报 |
| **识别** | 测试中包含时间、随机数、并发、网络请求 |
| **规避** | Mock 时间/随机数/网络，使用固定种子，避免并发竞争 |

**错误示例：**

```javascript
// ❌ 依赖真实时间
it('should return current year', () => {
  expect(getYear()).toBe(2026);  // 明年就挂了
});
```

**正确示例：**

```javascript
// ✅ Mock 时间
jest.useFakeTimers().setSystemTime(new Date('2026-01-01'));
it('should return current year', () => {
  expect(getYear()).toBe(2026);
});
```

## 陷阱 4：测试之间共享状态

| 项目 | 说明 |
|------|------|
| **症状** | 测试 A 改了全局状态，导致测试 B 失败 |
| **危害** | 测试执行顺序影响结果，调试困难 |
| **识别** | 测试文件中有模块级变量被多个测试修改 |
| **规避** | 每个测试独立准备数据，使用 `beforeEach` 重置状态 |

**错误示例：**

```javascript
// ❌ 共享状态
let counter = 0;

it('should increment', () => {
  counter++;
  expect(counter).toBe(1);
});

it('should increment again', () => {
  counter++;
  expect(counter).toBe(1);  // ❌ 实际为 2，因为上一个测试改了它
});
```

**正确示例：**

```javascript
// ✅ 每个测试独立
let counter;

beforeEach(() => {
  counter = 0;
});

it('should increment', () => {
  counter++;
  expect(counter).toBe(1);
});

it('should increment from zero', () => {
  counter++;
  expect(counter).toBe(1);
});
```

## 陷阱 5：断言不具体

| 项目 | 说明 |
|------|------|
| **症状** | 用 `toBeTruthy()`、`not.toBeNull()` 等模糊断言 |
| **危害** | 测试通过了但值不对，Bug 被掩盖 |
| **识别** | 断言中没有具体的期望值 |
| **规避** | 始终断言具体值：`toBe(42)`、`toEqual({ name: 'Alice' })` |

**错误示例：**

```javascript
// ❌ 模糊断言
expect(result).toBeTruthy();
expect(result).not.toBeNull();
```

**正确示例：**

```javascript
// ✅ 精确断言
expect(result).toBe(42);
expect(result).toEqual({ name: 'Alice', age: 30 });
```

## 陷阱 6：异步测试未等待

| 项目 | 说明 |
|------|------|
| **症状** | 测试在异步操作完成前就结束，假通过 |
| **危害** | 异步逻辑有 Bug 但测试显示绿色 |
| **识别** | 测试中调用了 async 函数但没有 await/return Promise |
| **规避** | 使用 `await`、`returns`、或 Jest 的 `done` 回调 |

**错误示例：**

```javascript
// ❌ 没有 await
it('should fetch data', () => {
  fetchData().then(data => {
    expect(data).toBeDefined();
  });
});
```

**正确示例：**

```javascript
// ✅ 使用 await
it('should fetch data', async () => {
  const data = await fetchData();
  expect(data).toBeDefined();
});
```

## 陷阱 7：测试代码有逻辑

| 项目 | 说明 |
|------|------|
| **症状** | 测试代码中包含 if/else、循环、复杂计算 |
| **危害** | 测试本身的 Bug 比被测代码还难发现 |
| **识别** | 测试函数超过 10 行，或包含条件分支 |
| **规避** | 测试代码应该直白、线性、重复数据多于逻辑 |

**错误示例：**

```javascript
// ❌ 测试代码有逻辑
it('should handle all cases', () => {
  for (let i = 0; i < 100; i++) {
    if (i % 2 === 0) {
      expect(process(i)).toBe('even');
    } else {
      expect(process(i)).toBe('odd');
    }
  }
});
```

**正确示例：**

```javascript
// ✅ 直白、线性
it('should return even for 0', () => {
  expect(process(0)).toBe('even');
});

it('should return odd for 1', () => {
  expect(process(1)).toBe('odd');
});
```

## 陷阱速查表

| 陷阱 | 一句话识别 | 一句话规避 |
|------|-----------|-----------|
| 只测 Happy Path | 测试文件里没有 throw/error/null | 强制要求每个函数至少 3 个测试 |
| 过度 Mock | Mock 了被测函数本身 | 只 Mock 外部依赖 |
| 脆弱测试 | 测试有时绿有时红 | Mock 时间/随机数/网络 |
| 共享状态 | 测试执行顺序影响结果 | beforeEach 重置状态 |
| 断言不具体 | 用了 toBeTruthy/not.toBeNull | 始终断言具体值 |
| 异步未等待 | async 函数没 await | 使用 await/done |
| 测试有逻辑 | 测试里有 if/for | 测试代码线性直白 |
