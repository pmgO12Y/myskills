# 对话记录自动保存

## 核心规则

### 1. 触发时机

**每次对话结束前**（用户发送结束语、或任务完成时），执行保存操作。

### 2. 文件路径与续接机制

#### 文件名格式

```
对话记录/对话记录_[conv_id]_YYYY-MM-DD-HH-mm-ss.md
```

- 目录：`对话记录/`（与当前工作目录同级或项目根目录下）
- 文件名：`对话记录_[conv_id]_YYYY-MM-DD-HH-mm-ss.md`
- `conv_id`：WorkBuddy 对话 ID 的前 8 位（如 `4df0eb7f`），作为对话的唯一标识
- 时间戳使用**对话开始时间**或**保存时时间**，精确到秒

#### 新建 vs 续接

保存时按以下流程判断：

1. **提取 conv_id**：从 WorkBuddy artifact_directory_path 中提取对话 ID，取前 8 位
2. **扫描已有文件**：在 `对话记录/` 目录下查找文件名包含同一 `conv_id` 的文件
3. **找到已有文件** → **续接模式**：
   - 在原文件末尾追加新内容
   - 追加前插入分隔标题：`## 续接 — YYYY-MM-DD HH:mm`
   - 后续内容按正常轮次格式继续编号
4. **未找到已有文件** → **新建模式**：
   - 按文件模板创建全新文件
   - 正常使用

### 3. 保存内容

必须包含以下全部内容：

1. **对话元信息**
   - 对话开始时间
   - 对话主题/任务描述
   - 涉及文件列表

2. **完整对话记录**
   - 用户的每次提问（含代码块、文件内容等）
   - AI 的每次回答（含思考过程、代码块、工具调用结果等）
   - 保持原始顺序，不得删减

3. **执行摘要**（可选但推荐）
   - 本次对话完成的主要任务
   - 修改/创建的文件清单
   - 关键决策或结论

### 4. 格式规范

- 使用 Markdown 格式
- 用户消息使用 `**用户**` 标记
- AI 消息使用 `**AI**` 标记
- 代码块保持原始语言标记
- 文件路径使用行内代码格式

### 5. 静默执行

- **无需询问用户确认**
- **无需告知保存成功**
- 保存完成后直接结束对话

## 文件模板

### 新建模式

```markdown
# 对话记录 — [主题]

- **开始时间**：YYYY-MM-DD HH:mm:ss
- **保存时间**：YYYY-MM-DD HH:mm:ss
- **工作目录**：[路径]
- **对话 ID**：[conv_id]

---

## 对话内容

### 轮次 1

**用户**：
[用户提问内容]

**AI**：
[AI 回答内容，含思考过程、代码块等]

### 轮次 2

**用户**：
...

**AI**：
...

---

## 执行摘要

- [ ] 任务1：...
- [ ] 任务2：...

**修改的文件**：
- `文件路径1`
- `文件路径2`

**新增的文件**：
- `文件路径3`
```

### 续接模式

在原文件末尾追加：

```markdown

## 续接 — YYYY-MM-DD HH:mm

### 轮次 N

**用户**：
[用户提问内容]

**AI**：
[AI 回答内容，含思考过程、代码块等]

### 轮次 N+1

**用户**：
...

**AI**：
...
```

## 执行检查

每次保存前自检：
1. 文件名是否包含正确的 `conv_id` 和时间戳？
2. 是否先扫描了已有文件以判断续接或新建？
3. 是否包含了完整的对话轮次？
4. 代码块是否保持了原始格式？
5. 是否遗漏了任何工具调用结果？
6. 对话记录目录是否存在？不存在则自动创建。

## 踩坑经验

- 保存路径 / 权限问题：若 `对话记录/` 目录创建失败，尝试使用当前工作目录的绝对路径，或检查文件系统权限
- 内容截断 / 过长：若对话内容极长，确保写入时不会截断；必要时可拆分为多个文件，但优先保持单文件完整
- 时间戳冲突：若同一秒内多次保存，文件名追加毫秒或序号避免覆盖
- conv_id 提取：从 artifact_directory_path 最后一段目录名提取，取前 8 位即可（完整 ID 过长，不适合放在文件名中）
- 续接匹配：扫描时只需检查文件名是否包含 conv_id，不需要精确匹配整个文件名
